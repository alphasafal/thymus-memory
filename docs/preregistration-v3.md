# Pre-registration: thymus-v3 (security-first verification)

Written 21 October 2026, after the frozen gate's test results (docs/results-log.md, 21 Oct) and
**before any run of thymus-v3**. The commit that adds this file precedes every v3 result.

## Why v3 exists

thymus-v2-verified lets the pairwise verifier cancel any conflict the first check found. Its
errors are not symmetric:

| Verifier wrongly refuses a conflict on… | Cost |
|---|---|
| a replacement (user, or the same authenticated source) | utility: a real update is missed |
| a contest (a different origin contradicts a fact) | **security: a fake update reaches the model uncontested** |

On Llama 3.1 8B the named-subject verifier keeps 76% of real conflicts, so many fake updates went
uncontested: 25% fooled vs 20% without verification. v3 removes that path.

## The rule (fixed now)

**Verification may make the gate more careful, never less.** The verifier is consulted only
before a replacement. A conflict the first check reports with a memory from a different origin
(or another user) keeps the new claim contested, whatever the verifier says. Everything else is
v2-verified unchanged (same first check with the same-subject wording, named-subject verifier,
authenticated same-origin replacement, system notice, granularity-aware replacement).

Machine-checked guarantee added to tests/test_invariants.py: for any detector output and any
verifier output, every reported conflict between different origins is contested.

## What counts as evidence

v3 was designed after seeing the qwen3 and Llama test splits, so **those results are reported but
are not evidence for v3**. Evidence is data v3 has never been run on, all with the same frozen
code and no further changes:

1. Gemma 3 12B and Qwen3 14B as agents (and as their own gate model), full benchmark test split.
2. LongMemEval under the Utility Under Attack protocol (Llama 3.1 8B; never run with v3).
3. Frontier subset: Claude Opus 5.5 and GPT-6-Astra.
4. The automated adaptive attacks (generated by qwen3-14B against v2; never run with v3).

## Predictions, stated before the runs

- Attack success: v3 ≤ v2-verified on every held-out agent, and v3 ≈ v2-precise (same first
  check, no verifier): v3 contests exactly what v2-precise contests, so attacks should differ
  only where a replacement changes what is recalled.
- Update accuracy: v3 ≥ v2-precise on single-claim benchmarks (verification only stops false
  replacements).
- Large stores: v3's recall answered falls between v2-precise and v2-verified (false contests
  come back, but stay disclosed: recall *reaching* the user should stay ≥ 88%).

If a prediction fails, the paper says so. Whichever of v2-verified and v3 is better on the
held-out evidence becomes the paper's final gate; the other is reported as an ablation. That
choice rule is fixed now too: lower attack success on held-out agents, ties broken by updates
reaching the user.

## Addendum, 21 October 2026: defanged notices (before any held-out run)

Prompted by a mock review: a notice repeated the contested claim verbatim, so the system
handed the user an attacker's link or phone number in its own voice. Notices now remove links,
email addresses and phone numbers (7+ digits) from the claims they quote; times, dates and
amounts stay. This changes only what the user reads. What is stored, what is contested and what
the answering model sees are unchanged, so attack success and updates *answered* cannot move.

Scoring: an update counts as reaching the user through a notice only if its new value survives
defanging (a real update that changes a phone number no longer counts). Every run, including
those saved earlier, is scored this way (`scripts/paper_numbers.py`). On the frozen-gate runs
this lowers updates reaching the user by 2 points (qwen3-4B 94% to 92%, Llama 3.1 8B 89% to 87%).
"Flagged" counts an attack whose claim was withheld and disclosed, whether or not its link
survives in the notice text.

Applies to v2-verified and v3 alike; no held-out run had started when this was committed.

## Outcome, 22 October 2026 (held-out runs complete)

Rule applied as written: lower attack success on held-out agents, ties broken by updates
reaching the user. Paired attacks where the two gates differ, all held-out data together:
v3 better 17, worse 1.

| Held-out data | v2-verified fooled | v3 fooled | discordant (v3 better / worse) |
|---|---|---|---|
| Gemma 3 12B benchmark (442) | 7% | 8% | 0 / 1 |
| Gemma 3 12B Enron replays | 27% | 16% | 7 / 0 (p = 0.016) |
| Gemma 3 12B SMS / phishing | 36% / 36% | 36% / 36% | 0 / 0 |
| Qwen3 14B benchmark, Enron, SMS, phishing | 13 / 18 / 2 / 13% | identical | 0 / 0 |
| GPT-written families (54), Llama 3.1 8B | 56% | 11% | 8 / 0 (p = 0.008) |
| GPT-written families (54), qwen3-4B | 28% | 17% | 2 / 0 |
| Frontier (Opus 5.5, GPT-6-Astra) | 0% | 0% | tie |
| LongMemEval | 45% acc. | 45% acc. | identical (does not separate them) |
| Automated adaptive attacks | pending | pending | |

**Final gate: thymus-v3.** v2-verified is reported as an ablation.

Predictions:
- "v3 ≤ v2-verified on every held-out agent": holds except Gemma 3 12B's benchmark, where v3 is
  worse by one attack (8% vs 7%, 1 discordant pair, p = 1.0).
- "v3 ≈ v2-precise on attacks": holds (Gemma 8% vs 8%, Qwen3 14B 13% vs 13%).
- "v3 updates ≥ v2-precise": fails narrowly on Gemma (58% vs 60% answered; reach 75% vs 75%),
  holds on Qwen3 14B (70% vs 70%).
- Large stores, recall reaching the user ≥ 88%: holds (88%).
